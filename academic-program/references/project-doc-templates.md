# 项目文档模板

初始化或修复科研项目时使用以下大纲。文件名使用英文，正文使用中文。请根据实际项目调整目录、论文目标和研究路线；最终项目文档必须具体、完整，并能直接供后续会话阅读。

## `project-files.md`

```markdown
# Project Files

## 后续对话启动必读文档

后续每次新对话或新任务开始时，先按顺序阅读根目录三份文档：

1. `project-files.md`：了解项目目录、文件分工和默认查找入口。
2. `project-rules.md`：了解文件管理、实验记录、代码开发、论文写作和协作规则。
3. `project-plan.md`：了解当前研究路线、论文目标、实验路线和开发优先级。

## 项目主要目的

简述研究问题、研究对象、核心假设、目标论文或成果形态。

## 当前结论边界

- 已证实：
- 合理推断：
- 暂不能声称：
- 需要新增证据：

## 目录结构

- `docs/`：研究计划、实验方案、实验记录、阶段总结和验收清单。
- `paper/`：论文稿件、图表、表格、模板、补充材料和投稿相关文件。
- `references/`：参考文献 PDF、BibTeX/RIS、阅读笔记和引用清单。
- `code/`：研究代码、脚本、配置、测试和 notebooks。
- `data/`：项目数据或小型样例数据；大型共享数据应单独说明。
- `outputs/`：实验输出、图像、指标、日志和中间结果。

## 后续对话使用建议

- 问研究路线和论文目标：先看 `project-plan.md`。
- 问文件放置和开发规范：先看 `project-rules.md`。
- 问目录和材料入口：先看本文件。
```

## `project-rules.md`

```markdown
# Project Rules

## 每次对话启动阅读顺序

先读 `project-files.md`，再读 `project-rules.md`，最后读 `project-plan.md`。

## 文件命名规范

- 计划：`YYYY-MM-DD_research-topic_plan_v01.md`
- 实验记录：`YYYY-MM-DD_experiment-name_record_v01.md`
- 输出目录：`YYYY-MM-DD_experiment-name_key-params_v01/`
- 论文图表：`figN_figure-topic_v01.ext`

## 目录放置规范

- 文档与实验记录放 `docs/`。
- 稿件与论文资产放 `paper/`。
- 参考文献和阅读笔记放 `references/`。
- 代码、配置和测试放 `code/`。
- 原始或共享数据放 `data/` 或共享数据目录。
- 实验结果放 `outputs/`。

## 实验记录规范

每次实验记录目的、输入数据、代码入口、参数、输出目录、指标、图表、结论、失败原因和下一步。

若实验使用标签、参考真值、人工标注、仿真数据或外部元数据，必须记录其来源、独立性和局限。

## 代码开发规范

使用相对路径；共享数据不复制；输出写入 `outputs/`；修改后运行相关验证；不做无关重构。

对关键输入设置硬校验：文件尺寸、格式、缺失值、重复样本、标签合法性、训练/测试泄漏、坐标或元数据一致性。校验失败时先写失败记录，不继续生成正式结论。

## 论文写作规范

论文目标、图表、表格、参考文献和实验结论要可追溯。区分已证实结果、解释性推断和未来工作。

每个主要 claim 都应能追溯到实验记录、脚本入口、输出文件和图表。不要把候选选择、内部验证或相关性结果写成端到端、泛化性或因果性结论。

## 对话协作规范

新任务先判断属于研究构思、实验规划、代码执行、结果总结、论文写作，还是投稿修改。
```

## `project-plan.md`

```markdown
# Project Plan

## 项目总体目标

说明研究问题、科学意义、技术路线、预期贡献和目标论文类型。

## 当前研究内容

说明当前阶段正在解决的问题、已有基础、关键假设和主要难点。

## 开发目标

- 短期目标：例如会议论文、初步实验、baseline 或数据集整理。
- 中期目标：例如完整方法、消融实验、对比实验和论文图表。
- 长期目标：例如期刊论文、系统扩展、跨数据验证或开源复现。

## 实验路线

列出数据、baseline、方法版本、评价指标、消融实验、负对照或鲁棒性测试。

## 证据链与论文主张映射

| 论文主张 | 支撑实验/分析 | 输出文件 | 当前状态 |
| --- | --- | --- | --- |
|  |  |  | 已证实/待验证/未来工作 |

## 代码路线

说明主要模块、入口脚本、配置方式、输出位置和测试方式。

## 论文路线

说明目标会议或期刊、篇幅、核心贡献、预期图表、参考文献方向和写作顺序。

## 当前优先级

按 1、2、3 写清下一阶段最重要的工作，避免未来对话跑偏。

## 风险与待验证事项

列出数据质量、标签可靠性、评估泄漏、负对照、鲁棒性、复现实验和投稿格式方面的风险。
```

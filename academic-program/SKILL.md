# 科研项目管理

按当前任务维护可复现的科研工作区，不强制启动完整研究流程。用户的明确范围和选择优先于本 skill 的默认约定。输出语言遵循用户明确选择或项目现有主语言；没有明确选择时跟随用户当前语言。

## 入口与任务分流

仅当任务需要写文件、运行实验或依赖项目结构时，定位实际项目根目录并读取当前宿主适用的 agent 指令入口（如 `AGENTS.md`、`CLAUDE.md` 或等价文件）；纯咨询只读取回答所需材料。不要把临时工作目录当成研究项目根目录。

| 当前任务 | 加载与动作 |
| --- | --- |
| 咨询、解释代码、讨论想法 | 只读相关材料，不因使用本 skill 创建管理文件。 |
| 修改已有代码 | 读取相关入口、适用约束和代码，执行与变更相关的验证。 |
| 规划、运行实验或总结结果 | 读取当前任务和相关方案，按需读取 [实验与绘图规则](references/experiment-evidence.md)；结果可能改变方向或产生新贡献时，再读取 [方向与创新复盘](references/direction-innovation.md)。 |
| 撰写论文结论或制作科研图 | 加载相关证据，读取 [实验与绘图规则](references/experiment-evidence.md)。 |
| 续接项目、阶段复盘或评估研究方向 | 读取当前状态和相关证据，按需读取 [方向与创新复盘](references/direction-innovation.md)。 |
| 初始化或整理项目 | 复用已有入口；需要新增或迁移时读取 [项目文档模板](references/project-doc-templates.md)。 |

## 文档数量与职责

- 不强制创建固定数量的 Markdown 文件。一次性任务可以不创建管理文档。
- 小项目需要长期约定时仅用当前宿主已有的 agent 指令文件，当前工作可用几行说明。
- 持续科研项目默认两类入口：一份 agent 指令文件保存稳定约定、关键目录和运行/验证入口；`PROJECT.md` 保存研究目标、当前阶段、近期任务、阻塞项及证据链接。多宿主项目指定一份稳定规则正文，其他宿主文件仅作简短适配或转向，避免维护冲突副本。
- 已有 `AGENTS.md`、`CLAUDE.md` 或等价指令文件只合并相关内容，保留原有指令；不修改父目录或无关项目的配置。
- 兼容 `project-files.md`、`project-rules.md`、`project-plan.md` 及同等现有入口；不自动创建并行文档，不因缺少新文件阻塞任务。实际适用的旧规则仍需遵守。
- 仅在用户要求迁移或整理时合并：检查原内容及引用，保留唯一事实来源并修复链接；旧文件删除须在明确授权范围内。
- 每项事实只在一处维护，其余位置用链接。历史实验和已完成阶段放专题记录，不持续追加到启动入口。

## 上下文与更新预算

- 从入口定位后读取相关文件或章节；普通代码修改不默认加载完整研究计划。
- 不重复读取同一会话中已读且未变化的内容；文件变化、上下文丢失或证据冲突时重新核实。
- 先用定向文件名/关键词检索再扩大范围；默认排除原始数据、运行产物、缓存、构建目录和历史归档的大范围内容扫描，任务指定证据除外。
- 大日志先看状态、错误和必要上下文，不足再扩大；完整日志保留在磁盘。`.gitignore` 不替代读取范围控制。
- 入口只列关键路径，不维护完整文件清单。新增 agent 指令文件建议约 60 行以内、`PROJECT.md` 约 100 行以内；这是软目标，不得为压缩删除必要约束或已有指令。
- 只在目录、规则或研究状态实际改变时更新对应文档；不为每次对话生成总结、版本副本或重复转述指标。

## 研究方向与阶段复盘

- 在续接项目、阶段转换、出现实质性新证据或一条支线持续投入时，对照项目的核心科学问题、目标成果、当前假设和下一项决定性验证，判断当前工作是 `ALIGNED`、`SUPPORTING`、`EXPLORATORY`、`DRIFT_RISK` 还是 `PIVOT_CANDIDATE`。只读取作出判断所需的当前状态和证据，不默认扫描全部历史。
- 发现 `DRIFT_RISK` 时简要说明偏离点、依据和回到主线的建议，不因此停止安全且仍有价值的当前工作。只有继续工作会实质改变核心目标、论文主张、成本或授权范围时才请求用户决定。
- 阶段结束、出现稳定的新现象或有信息量的负结果时，提炼创新候选，记录潜在贡献、已有证据、关键缺口、区别对象和下一项决定性验证。未经充分文献对照时只称“创新候选”，不声称学术新颖性已经成立。
- 提醒采用事件触发：核心假设受损、连续工作未降低关键不确定性、主张超过证据、方向漂移或出现高价值创新候选时及时提示。相同事项不重复提醒；未解决事项只保留一条状态记录，不要求为每次提醒暂停。
- 需要维护研究罗盘、方向状态、转向判断或创新候选时，读取 [方向与创新复盘](references/direction-innovation.md)。

## 文件生命周期

优先沿用已有目录和工具链，以下仅为新项目默认值，按需创建：

| 路径 | 职责 |
| --- | --- |
| `code/` | 可复用代码、配置、测试与 notebooks。 |
| `data/` | 原始数据或外部数据位置说明；原始输入只读，大型共享数据不复制。 |
| `work/` | 临时脚本、调试文件和可重建中间产物。 |
| `docs/experiments/` | 实验设计、解释、失败记录与结论。 |
| `docs/archive/` | 已完成阶段的历史计划，默认不加载。 |
| `outputs/runs/<run-id>/` | 单次运行的配置、指标、日志、图和结果，不覆盖其他运行。 |
| `paper/` | 稿件及实际采用的图表、投稿资产，记录来源运行和生成入口。 |
| `references/` | 文献索引、引用导出和阅读笔记；已有文献管理器继续作为来源，避免重复复制 PDF。 |

- 根目录不放临时脚本、日志或测试图片；使用项目相对路径或显式配置的外部路径。
- 版本控制下的源码、计划和稿件使用稳定文件名；实验使用唯一编号，例如 `20260910-153000_kr-baseline`，冲突时生成新编号，禁止覆盖。
- 参数写入配置，不堆进长文件名。正式导出只有确需冻结版本时才另存版本。
- 每个实验用一份全过程文档持续记录方案、运行、失败修正、结论及清理情况，不为每次重跑另建总结。
- 只清理本任务明确产生、可安全识别且可重建的临时项；除非用户要求整理，不把全面清理或另写清理记录作为交付门槛。保留原始输入、最终成果和复现/失败诊断必要证据，不把所有 outputs 都当垃圾。

## 科研硬约束

- 确认性或论文支撑实验在运行前明确假设、输入、比较基线、指标、成功标准和停止条件；探索性诊断可按现有信息先行，并记录所用假设。只有缺失信息会实质改变有效性、安全性或成本时才询问；小型代码任务不强制重做研究规划。
- 对关键输入校验格式、维度、缺失项及适用的坐标/元数据一致性。校验失败保留失败记录，停止依赖该输入的实验，不伪造或静默修复原始数据。
- 区分程序执行成功、验证通过和科研主张成立；退出码为 0 不足以证明实验有效。
- 已证实结果须有直接证据；合理解释标明不确定性；未来工作不写成已有成果。记录真值来源和独立性，按科学问题设置防泄漏划分。
- 验收不只依据单一数值门槛：硬否决项必须满足；全部预设软性能门槛满足记为 `STRICT_PASS`。软门槛仅小幅未达，但差距处于有依据的容差内，改进方向正确且趋势或效果清晰时，可记为 `PRACTICAL_PASS`，并明确报告未达指标、差距、容差依据和适用范围。容差可依据预设范围、测量不确定度、baseline 波动或应用意义；若运行后才确定，须标明为探索性判定并安排独立复核。不得挑选样本、隐藏失败或临时改变统计口径制造通过，不做影响实验可比性的无关重构。
- 科研绘图默认简洁英文、Times New Roman、放大且不重叠的字体；图像仅导出 PNG。布局与导出细则按需读取实验与绘图规则，用户明确指定的要求优先。

## 完成反馈

简述实际变化、验证结果和必要限制；存在阻塞时给出下一步。只在管理文档发生变更时说明它们，不逐项汇报读过的文件，不为小任务输出完整研究报告。
